RadioBOSS Song Request Bundle

Customer Help - Bundle v1.2.0
Song Request System v1.6.0 + SongSync Engine v1.8.0

Station-neutral package: this bundle contains no station-specific names, URLs, passwords or server paths. Enter your own settings during setup.

1. What is included?

ComponentPurpose
WebPublic song search and request page, request protection, queue position and estimated play time.
SongSyncReads your RadioBOSS music library, creates the public catalog and private filename lookup, and can upload them by SFTP.

The system can operate with one station or an optional second station. Each station uses its own catalog, request state and RadioBOSS API connection.

2. Requirements

RadioBOSS computer

  • Windows 10 or Windows 11
  • RadioBOSS with a SQLite or MySQL/MariaDB music library
  • RadioBOSS Remote Control API enabled
  • Network access to your web server

Web server

  • PHP 8.0 or newer
  • PHP cURL and JSON support
  • SFTP access if you want SongSync to upload the catalog automatically
  • Network access from the PHP server to the RadioBOSS Remote Control API

3. Quick installation

  1. Upload the contents of the Web folder to the desired directory on your web server.
  2. Open install.php in your browser.
  3. Enter your station name, timezone, RadioBOSS API address/password and request settings.
  4. If you use a second station, enable it in the installer and enter its separate settings.
  5. On the RadioBOSS computer, run SongSync/RadioBOSS-SongSync-Setup.exe.
  6. Select the RadioBOSS music database and configure the public/private export targets.
  7. Configure SFTP if the catalog should be uploaded automatically.
  8. Run SongSync once and confirm that the web page can see the catalog.
  9. Make a test request and verify that RadioBOSS receives it.

For the detailed installation order, also see QUICK-START.md.

4. SongSync setup

SongSync reads your RadioBOSS library but does not modify it. It creates public catalog files for the website and a private lookup file used to translate a listener's selection back to the correct audio file.

Keep the private lookup directory protected from public web access. If you use SFTP, the setup wizard can store the required connection settings in the local SongSync configuration.

5. Web request setup

The web installer creates config.php. This file contains your own station and API settings and should never be published or committed to a public repository.

Default request slots are at minute :15 and :45. Queue position and estimated play time remain part of the normal request flow.

6. Hourly artist repeat protection

Artist protection is enabled by default with ARTIST_HOURLY_PROTECTION.

If a song by an artist has already been accepted as a request during the current station clock hour, another request for the same artist on that station is rejected, even when the listener chooses a different song.

Example: if an artist is requested at 14:12, another request for that artist is blocked until 15:00. The rule uses the configured station timezone and is applied separately per station.

The listener receives a clear message explaining that a song by this artist has already been requested this hour and should choose another artist.

7. Important request protection settings

SettingPurpose
IP_COOLDOWN_SECONDSMinimum wait before the same listener/IP can submit another request.
TRACK_COOLDOWN_SECONDSPrevents the same track from being requested again too soon.
MAX_REQUESTS_PER_HOURLimits the number of requests per listener/IP per hour.
ARTIST_HOURLY_PROTECTIONPrevents two accepted requests for the same artist within the same station clock hour.

8. One or two stations

For two stations, configure each station independently. Do not reuse API passwords, database paths or SongSync configuration files unless they are genuinely identical.

The main and secondary station have separate public catalogs, private lookup files, request state files and request logs.

9. Troubleshooting

The song list is empty

  • Run SongSync manually and check that it completes without errors.
  • Verify the selected music database.
  • Check that songs.json is present in the configured public data directory.
  • If SFTP is used, check host, username, authentication and target paths.

A request appears on the website but not in RadioBOSS

  • Verify that the RadioBOSS Remote Control API is enabled.
  • Check the API address, port and password in the web configuration.
  • Confirm that the web server can reach the RadioBOSS computer through the network/firewall.
  • Check that the private SongSync lookup file exists and is readable by PHP.

A listener cannot request another song by the same artist

This is expected when hourly artist protection is enabled. The artist becomes available again at the start of the next station clock hour.

The installer opens again

Make sure config.php exists and is readable by PHP. After a successful setup, keep the installer lock in place unless you intentionally want to reconfigure the system.

10. Updating an existing installation

Before updating: back up Web/config.php, the private data directories and SongSync/config.json.

Do not overwrite your live configuration with example files. After an update, review the changelog for new settings and run a manual SongSync export followed by one test request.

11. Security

  • Never publish API passwords, SFTP passwords or SSH private keys.
  • Never expose private lookup.json, request-state or request-log files through the public website.
  • Use HTTPS for the public request page.
  • Use firewall rules or a VPN/reverse proxy where appropriate when the RadioBOSS API must be reachable from a remote web server.

12. Support information

When requesting support, include the bundle version, Web version, SongSync version, your operating system, PHP version and the exact error message. Do not send passwords, private keys or complete configuration files containing credentials.
